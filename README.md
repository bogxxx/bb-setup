# bb-setup

My [bb](https://getbb.app) setup: my own plugins, skills, agent instructions, Claude Code role agents, the installed plugin list and plugin settings.

Companion to [ai-agents-setup](https://github.com/bogxxx/ai-agents-setup), which holds the Copilot and Cursor agents.

## What's here

| Path | What | How bb uses it |
|---|---|---|
| `plugins/bb-plugin-role-picker` | Composer Role control (regular / orchestrator) and the `role_choice` tool | bb runs it from here (`path:` source) |
| `plugins/bb-plugin-claude-subagents` | Subagents panel and `bb claude-subagents` | bb runs it from here (`path:` source) |
| `skills/provider-orchestration` | User skill that routes work to role agents | junction from `~/.bb/skills/provider-orchestration` |
| `claude/agents/` | Claude Code `orchestrator`, `explorer`, `planner`, `worker` | junction from `~/.claude/agents` |
| `claude/CLAUDE.md` | Global Claude Code instructions | copied to and from `~/.claude/CLAUDE.md` |
| `bb/AGENTS.md` | Instructions bb adds to every thread | copied to and from `~/.bb/AGENTS.md` |
| `bb/bin/copilot-acp.cmd` | Copilot ACP launcher that uses the Copilot-enabled gh account | copied to and from `~/.bb/bin/` |
| `bb/plugins.json` | Installed plugins (git, npm, local) and builtin on/off state | generated by `sync.ps1` |
| `bb/plugin-settings.json` | Plugin settings that differ from the defaults (secret fields are left out) | generated by `sync.ps1` |

Folders are live: editing them here changes what bb and Claude use right away. Windows can't link single files without admin rights, so the three files are copied, and the newer copy wins.

## Make a change

1. Edit it. Plugins, skills and agents can be edited in this repo. `AGENTS.md`, `CLAUDE.md` and the launcher can be edited in either place. Settings and installs go through the bb app or `bb plugin ...`.
2. For plugin code, rebuild and reload: `bb plugin dev plugins/<name>` watches and reloads, or run `bb plugin build plugins/<name>` and then `bb plugin reload <id>`.
3. Save it to GitHub:

   ```powershell
   .\scripts\sync.ps1 -m "What changed"
   ```

   This copies the files, exports the plugin list and settings, then commits and pushes. `-DryRun` shows what would change, and `-NoPush` commits without pushing.

`~/.bb/AGENTS.md` tells every bb agent to run `sync.ps1` after it changes the setup, so agent changes reach GitHub too.

### New plugin

```powershell
cd $HOME\src\bb-setup\plugins
bb plugin new my-thing          # creates bb-plugin-my-thing
cd bb-plugin-my-thing; npm install; bb plugin build
bb plugin install $PWD --yes
..\..\scripts\sync.ps1 -m "Add my-thing plugin"
```

## Set up a new machine

Install bb, git, Node.js and gh, start bb, then run:

```powershell
git clone https://github.com/bogxxx/bb-setup $HOME\src\bb-setup
& $HOME\src\bb-setup\scripts\install.ps1
```

It links the folders, copies the files, builds and installs the local plugins, installs the git and npm plugins, clones local plugins that have a git remote (such as `burn`), matches the builtin on/off state and applies the settings. You can run it again safely.

Not included: plugin secrets, bb account sign-in, gh and provider logins, `bb.db`, and thread data. Set those up by hand. `bb/plugin-settings.json` stores `provider-acp.customAgents`, and that value still has macOS paths for the Copilot agent. Check it on Windows.

## macOS

```bash
T=$(gh auth token --user bogxxx)
git clone https://x-access-token:$T@github.com/bogxxx/bb-setup ~/src/bb-setup
git -C ~/src/bb-setup remote set-url origin https://github.com/bogxxx/bb-setup
~/src/bb-setup/scripts/sync.sh -m "What changed"
```

`scripts/sync.sh` is the macOS counterpart of `sync.ps1`. Its first run is the install. It pulls first, then symlinks `~/.bb/skills/provider-orchestration`, `~/.claude/agents`, `~/.bb/AGENTS.md` and `~/.claude/CLAUDE.md` into the repo. macOS can link single files, so nothing is copied. Existing files are moved to `*.bak-<timestamp>`, and a local file that is newer than the repo copy is copied into the repo first. Then it commits and pushes. Options: `-m`, `--dry-run`, `--no-push`.

Plugins and plugin settings live on the bb server. When this Mac is only an enrolled host and the server runs on Windows, the script skips exporting them, so `plugins.json` keeps the Windows host's view. `--plugins` forces the export, and `--no-plugins` skips it.

Git pulls and pushes use the `bogxxx` gh account's token for that one command. The script never runs `gh auth switch`, because bb's Copilot integration depends on the active gh account. Set `BB_SETUP_GH_USER` to use another account.
